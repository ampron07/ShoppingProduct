# Stage 2 project instructions

1. Use Python 3.10 or newer and Streamlit. Keep filtering and scoring deterministic in Python; do not add an LLM to the running shopping application.
2. Retrieve actual sample products from `https://dummyjson.com/products/search` with a trimmed, nonempty keyword and `limit=0`. Use a finite timeout, check HTTP status and JSON structure, and present readable API errors. Never substitute invented data for API results.
3. Retain Stage 1 lowest-price mode: with no active filters, sort all matches by numeric price ascending and show at most five. Unused filters must impose no conditions. Preserve existing Stage 1 tests and behavior.
4. Normalize supported brand, category, rating, price, and dimensions without fabricating missing values. Reject boolean and nonfinite numeric values. Expose size/dimension constraints only after verifying their actual meaning and units; do not infer clothing sizes from dimensions.
5. Apply all mandatory constraints before ranking, using inclusive budget and rating boundaries. Match brand/category by trimmed, case-insensitive exact values. Unknown attributes cannot satisfy active constraints. Never silently relax conditions.
6. Rank all eligible matches before taking five; never reuse Stage 1's truncated result list for weighted recommendations. Use normalized price/rating scores with configurable finite, nonnegative weights summing to 1. Document formulas, unknown-value policies, and deterministic tie-breaking.
7. Keep HTTP and normalization in `product_search.py`, pure filtering/ranking in `product_ranking.py`, UI in `app.py`, and tests in `tests/`. Preserve the Stage 1 public search behavior while adding access to all matches. Use descriptive names and small functions.
8. Display conditions, title, price, brand, rating, available image, weighted score, and a brief explanation in weighted mode. Label unknowns and identify results as sample DummyJSON information, not live retailer offers. Suggest user-controlled constraint changes when nothing qualifies.
9. Use pytest with mocked API responses for combined constraints, exact boundaries, missing/invalid values, invalid weights, scoring, ties, no matches, API errors, and Stage 1 regressions. Include a ranking winner outside the five cheapest products. Keep live checks separate from repeatable tests.
10. Use `.agents/skills/product-ranking/SKILL.md` for Stage 2 work and retain `.agents/skills/product-search/SKILL.md` for Stage 1. Its five-result selection rule applies to lowest-price mode; Stage 2 must filter and score the full matching set first.
11. Work in separate reviewable steps. Complete only the current requested step, report changes/checks, and stop for user review. Do not change application code during instructions/skill setup.
12. Keep honest development evidence: three distinct tasks covering constraints, explicit `$product-ranking` ranking work, and UI/integration; compare the same narrow task from the same starting code with and without explicit skill invocation in isolated files. Record actual results, an actual edge-case correction, and a reflection draft for student personalization. Never claim tests, experiments, screenshots, or human review that did not occur.
